# Request-scoped stopping and chat navigation verification

- The chat composer replaces Send with a square Stop icon while a request is queued, starting, or running. Stop is scoped to a saved message ID, not the whole session; stale requests cannot cancel newer work.
- Tenant/write-role/origin checks protect the stop route. Migration `0010_request_cancellation` adds durable cancelling/cancelled message states. Worker claim, stop, and completion share the task row lock.
- Codex turns are interrupted; the private E2B bridge additionally terminates only managed process IDs owned by that request and waits for exit acknowledgement. Other request processes, conversation state, files, and queued follow-ups are preserved. Completed external actions are not rolled back.
- Live general-chat and public-repository tests passed: interruption persisted, the sandbox sleep process was independently verified absent, and follow-ups resumed the same Codex thread. No PR writes were performed.
- User prompts have a subtle tinted card. The reserved right gutter contains one bar per prompt, with the current prompt highlighted; hovering or tapping opens the prompt list. A centered down-arrow above the composer appears when scrolled away from the latest message. Per-reply arrows were removed at the user's request. Partial replies stay together during cancellation; Request stopped is a centered highlighted notice without an icon.
- Desktop/mobile stop and prompt-navigation checks, PostgreSQL cancellation/follow-up tests, provider/executor regressions, type checks and lint passed. This feature does not implement abandoned-worker recovery after a development hot reload.

# User-selected Markdown skills

- Skills supports a `+ Add` menu with upload/create choices, a blurred dismissible modal for create/edit/delete, required name/description/summary fields, and MD/TXT import. Uploads with `---` frontmatter fill name and description while placing the Markdown body in Summary; uploads without frontmatter preserve manually entered metadata. Skills are private to the creating user within their organization. Delete disables the saved skill and clears its future session selections; existing message snapshots remain intact.
- Typing `/` at a word boundary opens a searchable picker in both launch and follow-up composers. Selection chips can be removed; up to three skills stay enabled in the session. Keyboard arrows, Enter, Escape and mobile taps are supported. Names/descriptions/summaries are bounded to 100/500/20,000 characters; imported UTF-8 files are limited to 80 KB.
- Migration `0011_chat_skills` stores summaries, session selections and per-message snapshots. Both general and repository turns receive the selected summaries alongside existing general instructions. Removing selection explicitly revokes earlier skill context. No additional tools, GitHub authorization, credentials or native executable skill scripts are enabled.
- PostgreSQL CRUD/tenant/role/origin/selection/snapshot tests passed, as did desktop/mobile CRUD/upload/slash checks and existing Stop/navigation checks. Shared, web, executor and provider regressions passed. Live general and E2B repository chats both used a selected skill, then its edited version on the same thread; no file or GitHub changes were requested.

# PostHog observability foundation

- The Next.js client initializes PostHog through `instrumentation-client.ts`, identifies authenticated users by stable internal ID, associates their organization, and emits manually bounded page labels. Dynamic task IDs, unknown paths, prompts, responses, repository content, names and email addresses are not captured.
- Session Replay follows the requested password-only masking configuration: password fields remain masked, while ordinary text, non-password inputs, and rendered application content are recorded. Browser autocapture, SPA-aware pageviews, page-leave events, Web Vitals/performance, console recording, and exception autocapture are enabled so Web Analytics, dashboards, replays, and Error Tracking receive their native event types.
- The executor exports structured OTLP logs, PostHog-native request spans, request-count and duration metrics, and `$exception` events. Signals carry bounded service, environment, outcome, provider, duration, and error-class dimensions rather than high-cardinality task IDs.
- Each Codex turn emits a PostHog `$ai_generation` event linked to the native distributed trace and an opaque multi-turn session ID. AI Observability receives model, provider, latency, outcome, reasoning effort, actual composed input, streamed response, and command `$ai_span` records with tool input/output. Usage and cost are not fabricated when the provider does not report tokens.
- PostHog hosts are allowed by the web CSP. Web and executor environment templates document the public project token and ingestion host, while explicitly rejecting personal API keys. The server adapter accepts `POSTHOG_PROJECT_TOKEN` and retains the previous variable as a compatibility alias.
- Observability and web tests, lint, type checks and the optimized production build passed. Integration verification signals were flushed to the configured PostHog project for events, AI generations/spans, exceptions, structured logs, metrics, and traces.
